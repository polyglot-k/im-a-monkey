주제: 사진 업로드를 어떻게 받을지

지금 상황:
- 사용자가 올린 사진을 우리 API 서버가 받아서 파일 저장소에 다시 올린다.
- 사진 한 장은 평균 6MB다.
- 저녁 9시 무렵 API 서버 CPU가 75%까지 오른다. 업로드 요청이 몰리는 시간이다.
- 지난달 업로드 실패 신고가 40건 들어왔다. 대부분 저녁 시간대였다.

선택지 A: API 서버를 2대에서 4대로 늘린다.
- 코드 변경 없음. 이번 주 안에 적용 가능.
- 서버 비용이 월 60만 원 늘어난다.
- 사진 크기가 커지면 같은 문제가 다시 생길 수 있다.

선택지 B: 앱이 파일 저장소에 직접 올리게 바꾼다. API 서버는 업로드 주소만 발급한다.
- API 서버를 거치지 않아 업로드 부하가 사라진다.
- 앱 수정이 필요하다. 앱 심사까지 2주 정도 걸린다.
- 구버전 앱은 기존 방식을 계속 쓰므로 두 방식을 한동안 함께 유지해야 한다.
- 업로드 주소가 새면 남이 파일을 올릴 수 있어서 주소 유효 시간을 짧게(5분) 둔다.

나는 B를 추천해. 다만 2주 동안은 버텨야 하니 그 사이에는 서버를 임시로 3대로 늘리는 게 좋겠다고 생각해. 임시 증설 비용은 아직 계산 안 했어.
