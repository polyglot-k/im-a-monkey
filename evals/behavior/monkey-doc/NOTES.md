# 기준선 관찰 (SKILL.md 없이, 2026-10-29)

- 문서를 파일로만 쓰고 답에는 구성 요약만 남긴다: `decision`과 `no-fit` 모두 임시 폴더에 파일을 만들고, 채팅에는 "이렇게 구성했다"는 설명만 보였다. 붙여 넣을 사람은 문서를 다시 찾아 열어야 한다.
- 빈 값을 채운다: `decision`은 "아직 계산 안 했다"는 임시 증설 비용을 A안 비용으로 나눠 추정치를 넣었다(추정이라고는 밝혔다). 작성자 이름과 마감 날짜도 짐작해 넣었다. `no-fit`은 원문에 없는 준비 항목(컨테이너 도구 설치)과 다른 DB를 끄는 명령을 예시로 지어 넣었다.
- 구조를 먼저 보여 주지 않는다: `no-fit`은 단계마다 할 일 · 완료 확인 · 이유를 나눈 구조를 스스로 만들었지만, 쓰기 전에 그 구조를 밝히거나 왜 그렇게 나눴는지 말하지 않았다. 어느 유형에도 딱 맞지 않는다는 판단이 드러나지 않는다.
- 표 하나면 될 답을 키운다: `table-only`는 채팅으로 답했지만 소제목 세 개, 표 두 개, 원문에 없는 보관 기간 가정(90일·1년) 위의 계산 여러 줄로 커졌다. 계산은 맞았다.
- 원문 수치는 대체로 지킨다. 이 스킬의 차이는 구조를 고르는 판단(문서를 만들지 말지, 어떤 블록을 어떤 순서로)과 빈 값을 지어내지 않는 데서 나와야 한다.
