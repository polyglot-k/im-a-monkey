다음 주에 들어오는 신입 개발자가 첫날 혼자 보는 문서를 만들어 줘. 노트북에 개발 환경을 직접 세팅하면서, 각 단계를 왜 이렇게 하는지도 이해하게 하고 싶어. 사내 위키(마크다운)에 올릴 거야. 신입은 웹 개발 경험은 있지만 우리 서비스는 처음이야.

세팅 순서와 이유:
1. 런타임 버전 관리 도구를 설치하고 저장소에 적힌 버전을 쓴다. 이유: 버전이 다르면 테스트가 로컬에서만 통과하는 일이 있었다.
2. 저장소를 받는다: git clone 후 make bootstrap 실행. 이유: 의존성 설치와 git 훅 설치를 한 번에 한다. 훅은 커밋 전에 린트를 돌린다.
3. .env.example을 .env로 복사한다. 비밀 값은 직접 넣지 않고 make secrets로 받는다. 이유: 비밀 값을 메신저로 주고받다 유출된 적이 있다.
4. make db-up으로 로컬 DB 컨테이너를 띄운다. 끝나면 "db ready"가 찍힌다. 이유: 공용 개발 DB를 여럿이 쓰다 서로 데이터를 지운 일이 잦았다.
5. make seed로 예시 데이터를 넣는다. 끝나면 "seeded 120 users"가 찍힌다. 이유: 빈 DB에서는 화면 대부분이 비어 있어 동작을 확인할 수 없다.
6. make test로 테스트를 돌린다. 5분쯤 걸리고 마지막 줄에 "all passed"가 나와야 한다. 이유: 여기까지 통과하면 세팅이 끝났다고 본다.

자주 막히는 곳: 4단계에서 포트 5432가 이미 쓰이고 있으면 실패한다. 노트북에 DB를 따로 깔아 둔 경우다. 그 DB를 끄고 다시 하면 된다.
막히면 팀 채널에 어느 단계에서 어떤 메시지가 나왔는지 붙여서 물어보면 된다.
