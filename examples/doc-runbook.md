## 전

요청: "캐시 서버 재시작 런북 좀 써 줘. 메모 아래에 있어."

<!-- monkey-lint: off -->
메모: 캐시 노드는 한 대씩 재시작. 먼저 트래픽에서 빼기(`cache-ctl drain <노드>`). 재시작은 `systemctl restart cache`. 끝나면 `cache-cli ping`에 PONG 나오면 정상. 그 다음 다시 트래픽에 넣기(`cache-ctl undrain <노드>`). 재시작 중에 해당 노드 캐시 내용은 날아감. 노드가 여러 대인데 몇 대인지는 환경마다 다름.
<!-- monkey-lint: on -->

## 후

# 캐시 노드 재시작

노드를 한 대씩 트래픽에서 빼고, 재시작하고, `PONG`을 확인한 뒤 다시 넣어요. 끝나는 기준은 모든 노드에서 `cache-cli ping`이 `PONG`을 돌려주는 거예요.

- 전제: 각 노드에 `cache-ctl`과 `cache-cli`를 쓸 수 있는 권한이 있어요.
- 걸리는 시간: `<채울 값>`
- 끝난 기준: 재시작한 모든 노드가 `PONG`을 돌려줘요.

## 절차

노드마다 아래를 차례로 해요. 한 번에 한 대만 해요.

1. 노드를 트래픽에서 빼요.

   ```
   cache-ctl drain <노드>
   ```

   기대 출력: `<채울 값>`

2. 노드의 캐시 내용이 사라진다는 점을 확인하고 재시작해요.

   > 주의: 재시작하면 이 노드의 캐시 내용이 날아가요. 되돌릴 수 없어요.

   ```
   systemctl restart cache
   ```

   기대 출력: `<채울 값>`

3. 노드가 살아났는지 확인해요.

   ```
   cache-cli ping
   ```

   기대 출력: `PONG`

4. 노드를 트래픽에 다시 넣어요.

   ```
   cache-ctl undrain <노드>
   ```

   기대 출력: `<채울 값>`

5. 다음 노드로 넘어가요. 노드 수는 환경마다 달라서 `<채울 값>`대예요.

## 위험

- 재시작한 노드는 캐시가 비어서 시작해요. 그 노드로 가는 요청은 한동안 캐시 없이 처리돼요.
- 3번에서 `PONG`이 나오지 않으면 `<채울 값>`. 되돌리는 방법도 `<채울 값>`이에요.
- 막히면 몇 번 단계에서, 어떤 메시지가 나왔는지를 `<채울 값>`에 붙여서 물어보세요.

## 무엇을 바꿨나

<!-- monkey-lint: off -->
- 블록 순서는 howto 프로필대로 결론 → 절차 → 위험이에요. 맨 위에 전제, 걸리는 시간, 끝난 기준을 둬요.
- 메모에 없는 걸리는 시간, 기대 출력, 실패 대처, 되돌리기, 노드 수는 지어내지 않고 `<채울 값>`으로 남겼어요.
- "주의"는 되돌릴 수 없는 단계(재시작) 바로 앞에 하나만 뒀어요. 표, 각주, 용어표, 코드 지도는 쓰지 않았어요.
