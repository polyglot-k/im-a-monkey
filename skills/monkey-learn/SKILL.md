# monkey-learn

## 먼저 지킬 규칙

1. 지적을 그 문장 하나가 아니라 패턴으로 일반화해서 적어요. 회사, 사람, 제품, 경로 같은 고유 정보는 일반적인 말로 바꿔요.
2. 정규식은 쓰지 않아요. 정규식으로 잡을 가치가 있어 보이면 "저장소에 PR로 올릴 후보: <패턴 설명>" 한 줄만 남겨요.
3. 저장소의 `catalog/`와 `skills/`는 고치지 않아요. 쓰는 곳은 사용자 오버레이뿐이에요.
4. 구조의 칸은 사용자가 말했거나 방금 보여 준 구조에 있는 것만 적어요. 없는 칸은 물어보고, 답이 없으면 `<채울 값>`으로 두고, 추측해서 채우지 않아요.
5. 쓴 뒤에는 파일 경로와 추가한 줄을 그대로 보여 줘요. 보여 주지 않으면 저장한 게 아니에요.

## 경로

이 스킬이 로드될 때 보이는 base directory를 `<base>`라고 할게요.

```
python3 <base>/../../hooks/config.py path
```

이 명령이 찍는 폴더를 `<cfg>`라고 해요. 오버레이 파일은 다음 둘이에요. 폴더가 없으면 만들어요.

- `<cfg>/overlay/antipatterns.md`: 안티패턴 사례
- `<cfg>/overlay/types/<이름>.md`: 저장한 문서 구조

오버레이 폴더에 쓰기가 막히면 다른 곳에 우회해서 쓰지 말고, 막혔다고 알린 뒤 쓸 내용을 답에 보여 줘요.

스크립트가 안 돌면 `$XDG_CONFIG_HOME/im-a-monkey/`, 없으면 `~/.config/im-a-monkey/`를 `<cfg>`로 써요.

## 절차 A: 안티패턴 남기기

글에 대한 지적("무슨 말이야", "너무 짧아", "AI 같은데 이건 하지 마")을 규칙으로 남길 때예요.

1. **일반화.** 지적이 가리키는 문장을 찾고, 무엇이 문제인지 한 문장으로 적어요. 예: "식별자와 축약어 여러 개를 한 문장에 넣었다".
2. **같은 패턴 찾기.** `<base>/../../catalog/antipatterns.md`와 `<cfg>/overlay/antipatterns.md`를 읽고 같은 패턴이 있는지 봐요. 항목 제목과 "왜"를 읽고 판단해요.
3. **있으면 사례 추가.** 오버레이 파일에서 그 ID의 `### <ID> <이름>` 절을 찾아 아래에 한 줄을 붙여요. 절이 없으면 제목 한 줄과 함께 만들어요. 이름은 카탈로그에서 가져와요. U번호 절은 오버레이에 이미 있는 이름을 그대로 써요.

   ```
   ### W01 압축 설명
   - 사례: <일반화한 나쁜 예> → <고친 예>
   ```

4. **없으면 새 ID.** 심각도는 사용자에게 물어보고, 답이 없으면 중으로 해요. 오버레이 파일에서 `U`로 시작하는 ID 중 가장 큰 번호에 1을 더해요. 하나도 없으면 `U01`이에요. 카탈로그와 똑같은 형식으로 추가해요.

   ```
   ### U01 <패턴 이름>
   - 심각도: 상|중|하
   - 왜: <독자가 겪는 문제 한 문장>
   - 나쁜 예 → 고친 예: <일반화한 예> → <고친 예>
   - 잡는 곳: 판단
   ```

5. **보여 주기.** 파일 경로와 추가한 줄을 답에 붙여 넣어요. `monkey-human`이 다음 진단부터 이 파일을 읽는다고 한 줄 알려요.

사례는 사용자가 쓴 말이나 방금 쓴 문장에서 가져오되 고유 정보는 빼요. 고친 예를 모르면 지어내지 말고 "고친 예는 <채울 값>"으로 두고 사용자에게 물어요.

## 절차 B: 문서 구조 남기기

`monkey-doc`이 새 구조를 조립했고 사용자가 "이 구조 다음에도 쓰자"고 할 때예요.

1. **형식 확인.** 저장할 구조가 `monkey-doc`의 새 구조 형식(언제, 블록 순서, 길이감, 자세함, 가독성 장치, 요소 일곱 가지, 넣지 않는 것)을 다 갖췄는지 봐요. 빠진 칸은 방금 보여 준 구조에서 가져오고, 거기에도 없으면 물어보고 답이 없으면 `<채울 값>`으로 둬요.
2. **이름 정하기.** 사용자가 이름을 줬으면 그대로, 아니면 짧은 이름을 제안해요. 파일 이름은 `<이름>.md`예요. 같은 이름이 오버레이에 있거나 기본 유형(`<base>/../monkey-doc/types/`의 파일 이름과 `(영문 id)`)과 겹치면 덮어쓰지 말고 사용자에게 물어요.
3. **쓰기.** 유형 파일과 같은 형식으로 `<cfg>/overlay/types/<이름>.md`에 써요.

   ```
   # <이름> (<영문 id>)

   - 언제: <독자의 행동 한 줄>
   - 블록 순서: <blocks.md 이름> → <…>
   - 길이감: <하한>~<상한> 어절 | 없음
   - 자세함: <…>
   - 가독성 장치: <…>
   - 요소:
     - 각주: <쓴다|선택|쓰지 않는다> — <이유 한 구절>
     - 표: …
     - 그림: …
     - 콜아웃: …
     - 접기: …
     - 용어표: …
     - 코드 지도: …
   - 이 유형에 넣지 않는 것: <…>
   ```

4. **보여 주기.** 경로와 파일 전체를 답에 붙여 넣고, 다음부터 `monkey-doc`이 이 유형을 후보로 올린다고 알려요.

구조의 "언제"와 "넣지 않는 것"에 회사나 팀 고유 정보가 있으면 일반적인 말로 바꿔서 저장해요.

## 지적 종류별 일반화 예

| 지적 | 일반화 |
|---|---|
| "이게 무슨 말이야" | 풀어 쓰지 않은 축약어·식별자, 건너뛴 인과 단계. 대개 W01, W02, T02 |
| "너무 짧아" | 이유·예외·버린 대안이 빠짐. 새 패턴이면 U번호 |
| "AI 같아, 이거 하지 마" | 걸린 말투를 패턴으로. 카탈로그 A번호에 있으면 사례만 추가 |
| "이 구조 다음에도 쓰자" | 절차 B |

## 자주 하는 실수

| 실수 | 대신 |
|---|---|
| 지적받은 문장을 그대로 저장해요 | 어떤 문장에도 적용되는 패턴으로 바꿔요 |
| 카탈로그에 있는 패턴을 U번호로 또 만들어요 | 그 ID 절 아래에 사례 한 줄만 붙여요 |
| 정규식을 만들어 넣어요 | PR 후보 한 줄만 남겨요 |
| 저장하고 말없이 끝내요 | 경로와 추가한 줄을 보여 줘요 |
| 단순한 "AI 같아"에 파일을 써요 | 남기라는 말이 없으면 `monkey-human`에 맡겨요 |

## 마지막으로 지킬 규칙

- 오버레이에만 썼나요? 일반화했고 고유 정보가 없나요? 정규식은 없나요?
- 기존 ID면 사례만, 없으면 U번호 새 항목으로 카탈로그 형식을 지켰나요?
- 구조의 칸을 추측으로 채우지 않았나요? 없는 칸은 물어봤거나 `<채울 값>`인가요?
- 경로와 추가한 내용을 보여 줬나요?
