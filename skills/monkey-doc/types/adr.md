# ADR (adr)

- 언제: 나중에 "왜 이렇게 했지?"를 묻는 사람이 결정과 그 대가를 확인한다.
- 블록 순서: 결론 → 결정표 → 비교 → 위험 → 코드 읽기 지도
- 길이감: 150~400 어절 (상한 초과 → 결정이 둘 이상 섞였는지 보고 ADR을 나눈다, 하한 미만 → 비용이나 버린 대안이 빠졌는지 보고, 원문에 없으면 묻거나 자리만 남긴다)
- 자세함: 결정 당시의 제약, 날짜, 근거 수치를 구체적으로 쓴다. 비용(감수하는 것)은 반드시 쓴다. 버린 대안마다 버린 이유 한 줄. 구현 방법은 쓰지 않는다.
- 가독성 장치: 맨 위에 상태 한 줄(제안 / 채택 / 대체됨 → 새 ADR 링크). 짧은 문서라 섹션별 한 줄 결론과 접기는 쓰지 않는다.
- 요소:
  - 각주: 선택 — 결정 당시 근거 자료 링크. 나중 독자가 맥락을 되짚을 수 있게 남긴다.
  - 표: 선택 — 대안이 셋 이상일 때만. 둘이면 문장이 더 빠르다.
  - 그림: 쓰지 않는다 — 구조 설명은 동작 설명 문서의 몫이다. ADR은 결정과 이유만 담는다.
  - 콜아웃: 쓰지 않는다 — 문서 전체가 결정이라 따로 강조할 곳이 없다.
  - 접기: 쓰지 않는다 — 400어절 이하라 숨길 것이 없다.
  - 용어표: 쓰지 않는다 — 짧은 기록에 찾아보기는 필요 없다.
  - 코드 지도: 선택 — 결정이 구현된 커밋을 SHA로 고정해 둔다.
- 이 유형에 넣지 않는 것: 장점만 쓴 결정, 결정 뒤에 바뀐 사실로 본문을 고치기, 회의록.

## 쓰는 법

- 결정표는 표 대신 문단으로 써도 된다. 짧은 기록이라 네 칸(왜 나왔나 · 범위 · 선택지 · 결정과 이유)이 문단 안에 다 있으면 된다.
- 결정이 바뀌면 이 ADR을 고치지 않는다. 새 ADR을 쓰고 이 문서의 상태를 "대체됨"으로 바꿔 새 ADR을 링크한다. 상태 한 줄만 고친다.
- 비용은 "느려질 수 있다" 같은 흐린 말이 아니라 무엇을 포기했는지로 쓴다. 예: "목록 화면 응답이 한 번 더 조회하는 만큼 늦어지는 것을 받아들인다."
- 시간에 묶인 말("현재", "곧") 대신 날짜를 쓴다. 이 문서는 몇 년 뒤에 읽힌다.
