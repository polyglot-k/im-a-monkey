# 메시지 (message)

- 언제: 독자가 30초 안에 읽고 답하거나 한 가지를 한다. 메신저, 메일, PR 링크를 보내는 한 줄. PR 본문은 pr 유형이다.
- 블록 순서: 요청 → 결론 → 위험
- 길이감: 없음~150 어절 (하한 없음 — 한 줄로 끝나는 메시지도 충분하다. 상한 초과 → 문서로 쓰고 메시지에는 요청과 링크만 둔다)
- 자세함: 독자가 행동하는 데 필요한 것만 쓴다. 이유는 한 문장, 나머지는 링크로 보낸다.
- 가독성 장치: 첫 줄이 요청이나 결론이다. 제목을 달지 않는다.
- 요소:
  - 각주: 쓰지 않는다 — 메신저는 각주를 렌더하지 못하고 30초 독자는 아래까지 내려가지 않는다.
  - 표: 선택 — 최대 1개. 값 세 개 이상을 비교할 때만.
  - 그림: 선택 — 화면 캡처 정도, 최대 1개.
  - 콜아웃: 쓰지 않는다 — 글 전체가 짧아 따로 강조할 곳이 없다.
  - 접기: 쓰지 않는다 — 접힌 곳은 열리지 않는다. 길면 문서로 옮긴다.
  - 용어표: 쓰지 않는다.
  - 코드 지도: 쓰지 않는다 — 30초 독자는 코드를 열지 않는다.
- 이 유형에 넣지 않는 것: 배경 설명 여러 문단, 소제목, 장식용 볼드와 이모지.

## 쓰는 법

- 요청은 "누가, 무엇을, 언제까지"로 쓴다. 답하기 쉽게 선택지를 주면 더 좋다. 예: "A로 가도 될까요? 금요일까지 답 없으면 A로 진행할게요."
- 매체가 메신저면 마크다운 표가 깨질 수 있다. 표 대신 줄마다 "항목: 값"으로 쓴다.
