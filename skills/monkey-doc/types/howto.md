# How-to·런북 (howto)

- 언제: 독자가 지금 작업을 단계대로 따라 해서 끝낸다. 장애 대응 런북도 여기다.
- 블록 순서: 결론 → 절차 → 위험
- 길이감: 100~600 어절 (상한 초과 → 작업 단위로 런북을 나눈다, 하한 미만 → 기대 출력·실패 시 할 일·되돌리기가 빠졌는지 보고, 원문에 없으면 묻거나 자리만 남긴다)
- 자세함: 단계마다 정확한 명령, 끝났을 때 보이는 출력을 쓴다. 실패하면 할 일과 걸리는 시간은 원문에 있으면 쓰고, 없으면 `<채울 값>`으로 둔다. 이유는 독자가 단계를 건너뛰고 싶어질 곳에만 한 줄.
- 가독성 장치: 맨 위에 전제 · 걸리는 시간(원문에 있을 때) · 끝났다는 기준. 번호 단계. 섹션별 한 줄 결론은 쓰지 않는다(단계 자체가 결론이다).
- 요소:
  - 각주: 쓰지 않는다 — 따라 하는 중 시선이 아래로 튀면 어느 단계였는지 놓친다.
  - 표: 쓰지 않는다 — 단계 사이의 표는 흐름을 끊는다. 꼭 필요하면 절차 뒤 참고로 둔다.
  - 그림: 선택 — 갈림길이 있는 절차면 맨 앞에 흐름도 하나.
  - 콜아웃: 쓴다 — 되돌릴 수 없는 단계 바로 앞에 "주의".
  - 접기: 선택 — 드물게 필요한 실패 대처만. 매번 하는 단계는 접지 않는다.
  - 용어표: 쓰지 않는다 — 따라 하는 사람은 찾아보지 않는다. 낯선 말은 그 단계에서 푼다.
  - 코드 지도: 쓰지 않는다 — 따라 하는 사람은 코드를 읽지 않는다.
- 이 유형에 넣지 않는 것: 설계 배경 설명(동작 설명으로 나눈다), 결정 요청, 단계마다 붙는 긴 이유.

## 쓰는 법

- 조건은 지시 앞에 쓴다. "운영 환경이면 먼저 백업한다", "백업한다. 단 운영 환경이면"이 아니다.
- 명령은 복사해서 바로 쓸 수 있게 코드 블록에 넣는다. 사용자가 바꿔야 하는 값은 `<이름>`으로 표시한다.
- 실패했을 때 독자가 물어볼 곳과 붙여 넣을 정보(어느 단계, 어떤 메시지)를 맨 끝에 쓴다.
