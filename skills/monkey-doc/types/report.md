# 조사·장애 보고 (report)

- 언제: 독자가 무슨 일이 있었는지 알고 후속 조치를 정하거나 공유한다.
- 블록 순서: 결론 → 흐름 그림 → 예시 → 위험 → 요청 → 열린 질문 → 코드 읽기 지도
- 길이감: 200~800 어절 (상한 초과 → 결론 문서와 상세 부록으로 나눈다, 하한 미만 → 영향 범위·원인 확인 여부·후속 조치가 빠졌는지 본다)
- 자세함: 영향 범위와 수치는 측정·추정·미확인을 나눠 쓴다. 원인은 확인된 것과 가설을 나눈다. 조사하다 막힌 길은 결론을 바꿀 때만 쓴다.
- 가독성 장치: 맨 위 요약(영향 · 원인 · 조치를 세 줄로), 섹션별 한 줄 결론, 원본 로그는 접기.
- 요소:
  - 각주: 쓴다 — 수치마다 근거(쿼리, 로그, 대시보드)를 단다. 독자가 숫자를 믿을지 판단하게 하되 본문 흐름은 끊지 않는다.
  - 표: 쓴다 — 영향 수치(기간, 건수, 금액)는 표로 모은다.
  - 그림: 쓴다 — 타임라인이나 장애가 퍼진 흐름. 언제 무슨 일이 있었는지가 보고의 뼈대다.
  - 콜아웃: 선택 — 아직 남은 위험이 있을 때 "주의" 하나.
  - 접기: 선택 — 원본 로그, 조사 쿼리 전문.
  - 용어표: 쓰지 않는다 — 공유 대상이 넓으면 문장 안에서 푼다.
  - 코드 지도: 선택 — 원인 코드나 수정 커밋이 있을 때.
- 이 유형에 넣지 않는 것: 조사한 순서대로 쓴 일지, 누구 탓인지, 확인하지 않은 원인을 단정한 문장.

## 쓰는 법

- 결론 첫 줄은 "무엇이, 언제부터 언제까지, 누구에게 어떤 영향"이다.
- 원인이 확인되지 않았으면 결론에 "원인은 아직 확인하지 못했다"를 쓰고 가설을 열린 질문으로 보낸다.
- 후속 조치는 요청 블록에 담당과 시점을 붙여 쓴다. 담당이 없으면 "담당 미정"이라고 쓴다.
