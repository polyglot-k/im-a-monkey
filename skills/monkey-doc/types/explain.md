# 동작 설명 (explain)

- 언제: 독자가 시스템이 어떻게 움직이는지 이해해서 자기 일(수정, 디버깅, 질문)에 쓴다.
- 블록 순서: 결론 → 예시 → 흐름 그림 → 위험 → 코드 읽기 지도 (숙련 독자면 예시를 흐름 그림 뒤로 옮긴다)
- 길이감: 200~1000 어절 (상한 초과 → 질문 단위로 문서를 나눈다, 하한 미만 → 이유·예외·실제 값 예시가 빠졌는지 보고, 원문에 없으면 묻거나 자리만 남긴다)
- 자세함: 왜 그렇게 동작하는지(설계 이유)와 예외를 쓴다. 구현 세부는 독자가 할 일에 필요한 만큼만. 처음 보는 독자에게는 실제 값으로 끝까지 따라가는 예시 하나.
- 가독성 장치: 맨 위 요약, 섹션별 한 줄 결론, 드문 예외 경로는 접기.
- 요소:
  - 각주: 선택 — 역사적 이유 같은 곁가지 사실을 흐름에서 뺄 때.
  - 표: 선택 — 설정값이나 상태가 셋 이상일 때.
  - 그림: 쓴다 — 흐름과 구조가 이 유형의 핵심이다. 질문 하나에 그림 하나.
  - 콜아웃: 선택 — 독자가 자주 틀리는 예외 하나에 "주의".
  - 접기: 선택 — 드문 예외 경로. 대부분의 독자가 만나는 경로는 접지 않는다.
  - 용어표: 선택 — 낯선 용어가 다섯 개 이상이고 여러 섹션에서 되풀이될 때만, 문서 끝에.
  - 코드 지도: 쓴다 — 읽고 나서 코드를 열어 볼 독자가 많다.
- 이 유형에 넣지 않는 것: 결정 요청, 따라 할 절차(런북으로 나눈다), 코드에서 다시 만들 수 있는 목록 복사.

## 쓰는 법

- 문서 머리에 독자 수준을 한 줄로 정하고, 그에 따라 예시 위치를 고른다.
- 그림 자리는 `monkey-visual` 마커로 먼저 잡고, 본문에는 그림이 못 보여 주는 이유만 쓴다.
- 문장 단위 풀이(압축 설명 풀기, 식별자 뒤에 붙이기)는 `monkey-clear` 규칙을 따른다.
