# monkey-doc

## 먼저 지킬 규칙

1. 구조를 고르기 전에 의도 다섯 칸(독자 · 행동 · 시간 · 매체 · 수명)을 정해요. 다 채워지면 묻지 않고 한 줄로 밝혀요. 구조가 갈리는 칸이 비었을 때만 질문 하나에 추천 답을 붙여 물어요.
2. 표 하나로 답할 수 있으면 문서를 만들지 않아요. 채팅에서 표 하나와 몇 문장으로 답해요.
3. 유형마다 정해진 프로필(구성 · 길이감 · 자세함 · 가독성 장치 · 요소)을 따라요. 맞는 유형이 없으면 블록으로 새 구조를 조립하고, 그 프로필을 유형 파일과 같은 형식으로 먼저 보여 줘요.
4. 분량이 상한을 넘으면 줄이지 말고 나눠요. 맥락(이유, 버린 대안, 예외, 미확인)을 빼서 맞추지 않아요. 하한보다 짧으면 빠진 칸이 없는지 봐요.
5. 원문에 없는 수치, 이유, 단계, 명령, 범위, 조건을 지어 넣지 않아요. 빠진 칸은 원문에서 찾고, 없으면 `<채울 값>`이나 열린 질문으로 남겨요(범위·시간·되돌리기·실패 대처 포함). 칸을 채우려는 압박보다 이 규칙이 먼저예요.

## 파일

이 스킬이 로드될 때 보이는 base directory를 `<base>`라고 할게요.

- `<base>/intent.md`: 의도 다섯 칸, 물을 때와 묻지 않을 때, 행동 → 유형 표.
- `<base>/blocks.md`: 블록 12개와 요소(각주, 접는 상세 등)의 쓰는 규칙.
- `<base>/types/*.md`: 기본 유형 8개의 프로필. decision · adr · report · explain · howto · reference · message · study.
- 사용자가 저장한 유형이 `$XDG_CONFIG_HOME/im-a-monkey/overlay/types/*.md`(없으면 `~/.config/im-a-monkey/overlay/types/*.md`)에 있을 수 있어요. 있으면 읽고 기본 유형과 함께 후보에 올려요.

## 절차

1. **의도.** `intent.md`를 읽고 다섯 칸을 채워요. 다 채워지면 `의도: 독자 · 행동 · 시간 · 매체 · 수명 → 유형`을 한 줄로 밝히고 바로 써요.
2. **문서가 필요한지.** 값 몇 개의 비교, 예/아니오 답처럼 표 하나로 끝나는 질문이면 여기서 멈추고 채팅에 표로 답해요. 표 앞에 무엇을 보여 주는 표인지 한 문장, 표 뒤에 질문에 대한 답 한두 문장이면 돼요. 표는 하나, 소제목과 볼드는 없어요. 답이 원문에 없는 조건에 달려 있으면 그 조건을 가정해 계산을 펼치지 말고, 갈림 조건을 한 문장으로 말하고 확인할 것 하나를 물어요.
3. **유형 고르기.** 행동 → 유형 표에서 고르고 그 유형 파일을 읽어요. 오버레이 유형도 같은 방식으로 맞춰 봐요.
4. **맞는 유형이 없으면 조립.** 아래 "새 구조 조립"을 따라요. 두 유형을 섞어 쓰기로 했다면 그게 바로 새 구조예요. "두 유형을 합쳤다"는 말만으로 넘어가지 말고 형식을 채워 보여 줘요.
5. **초안.** 유형의 블록 순서대로 써요. 그림이 필요한 자리는 `monkey-visual` 초안 마커(`<!-- visual: flow | Q: 질문? -->`)로 먼저 잡아요.
6. **그림.** 마커를 `monkey-visual` 규칙대로 실제 그림으로 바꿔요. 마커는 하나도 남기지 않아요.
7. **문장.** `monkey-human`을 `fix` 모드로, 문서 파일 경로와 함께 불러요.
8. **검사.** 아래 "검사"를 돌리고 0건이 될 때까지 고쳐요.
9. **게시 전 체크.** 맨 아래 "마지막으로 지킬 규칙"을 하나씩 확인해요.

문서를 어디에 저장할지 듣지 못했으면 문서 전문을 답에 그대로 보여 줘요. 사용자가 그대로 붙여 넣을 수 있어야 해요. 검사용 파일은 시스템 임시 폴더에 만들고 검사가 끝나면 지워요.

## 새 구조 조립

맞지 않는다고 보는 때는 두 가지예요.

- 두 유형에 반씩 걸리는데, 나누면 독자의 행동이 끊길 때. 예: 따라 하면서 이유도 이해해야 하는 문서(How-to와 동작 설명이 반씩).
- 어느 유형의 "언제"와도 맞지 않을 때.

조립 순서:

1. 의도의 "행동"에서 출발해요. 첫 블록은 독자가 행동하는 데 가장 먼저 필요한 것이에요.
2. `blocks.md`에 있는 이름만으로 블록 순서를 정해요. 블록 12개에 더해 "요소와 가독성 장치" 절의 이름(점검 질문 같은)도 쓸 수 있어요. 같은 내용을 두 블록에 쓰지 않아요.
3. 가까운 두 유형의 프로필을 비교해서 길이감, 자세함, 가독성 장치, 요소를 정해요. 요소마다 쓴다 / 선택 / 쓰지 않는다와 이유를 한 구절씩 붙여요.
4. 아래 형식을 빠짐없이(언제부터 넣지 않는 것까지, 요소 일곱 가지 모두) 채워 답의 맨 앞, 문서 전문보다 먼저 보여 줘요. 사용자 답을 기다리지 말고 바로 이 구조대로 써요. 형식이 빠진 조립은 실패예요.
5. 다 쓴 뒤 다시 쓸 만한 구조면 `monkey-learn`으로 오버레이에 저장하자고 제안해요.

<!-- monkey-lint: off -->
```
# <새 유형 이름>
- 언제: <독자의 행동 한 줄>
- 블록 순서: <blocks.md 이름> → <…>
- 길이감: <하한>~<상한> 어절 | 없음
- 자세함: <무엇을 어디까지 풀어 쓰나>
- 가독성 장치: <맨 위 요약 / 섹션별 한 줄 결론 / 접기 중 무엇을>
- 요소:
  - 각주: <쓴다|선택|쓰지 않는다> — <이유 한 구절>
  - 표: …
  - 그림: …
  - 콜아웃: …
  - 접기: …
  - 용어표: …
  - 코드 지도: …
- 이 유형에 넣지 않는 것: <…>
```
<!-- monkey-lint: on -->

## 분량

- 유형 파일의 길이감이 기준이에요. 상한을 넘으면 목적이 섞였다는 신호예요. 목적별로 문서를 나누고 서로 링크해요.
- 하한보다 짧으면(L02) 유형이 요구하는 칸(이유, 버린 대안, 기대 출력 같은)이 빠졌는지 봐요. 빠진 칸은 원문에서 찾고, 없으면 `<채울 값>`이나 열린 질문으로 남겨요(범위·시간·되돌리기·실패 대처 포함). 분량을 맞추려고 내용을 지어 채우지 않아요. 다 있는데 짧으면 그대로 둬요.
- 길어도 읽히게 하는 건 가독성 장치예요. 맨 위 요약, 섹션별 한 줄 결론, 접는 상세 가운데 유형 파일이 정한 것을 써요.

## 코드 참조

- 본문에는 `파일:줄`이나 경로 약어를 넣지 않아요. 본문은 동작을 사람 말로 설명해요.
- 코드 참조는 문서 맨 아래 `## 코드 읽기 지도`에만 두고, 커밋 SHA로 고정해요. 항목마다 "여기서 무엇을 보나" 한 줄을 붙여요.

## 검사

```
python3 <base>/../../scripts/lint.py FILE --type <유형>   # 번역투·분량(L01 상한, L02 하한)
python3 <base>/../../scripts/visual.py FILE               # 남은 마커·캡션·표지 밀도
python3 <base>/../../scripts/coderef.py FILE --repo .     # 코드 읽기 지도가 있을 때만
```

- `--type`은 기본 유형 8개만 받아요. 새 구조나 오버레이 유형이면 `--type` 없이 돌리고, 길이감은 어절 수를 세어 직접 비교해요.
- L01은 나누라는 신호, L02는 빠진 맥락을 보라는 신호예요. L02는 다 확인했는데 짧으면 그대로 둬도 돼요.
- Python이 없거나 스크립트가 실패하면 멈추지 말고 스크립트 없이 체크리스트로 확인해요. "마지막으로 지킬 규칙"을 눈으로 하나씩 확인하고, 그렇게 했다고 보고에 적어요.

## 다른 스킬과 나누는 일

- 채팅에서 개념이나 동작을 쉽게 풀어 주는 일은 `monkey-clear`예요. 이 스킬은 문서 한 편의 구조를 정해요. 문서 안의 문장을 쉽게 쓰는 규칙은 `monkey-clear`를 따라요.
- 그림의 종류와 문법, 캡션, 콜아웃은 `monkey-visual`이에요.
- AI 티와 번역투 고치기는 `monkey-human`이에요. 이 스킬은 7단계에서 불러요.
- 구조는 그대로 두고 문장·말투만 다듬어 달라는 요청은 처음부터 `monkey-human`이에요. 이 스킬은 문서 구조를 다시 잡거나 새로 짤 때 써요.

## 자주 하는 실수

| 실수 | 대신 |
|---|---|
| "두 요금제 중 뭐가 싸?" 같은 질문에 소제목 달린 문서를 써요 | 채팅에서 표 하나와 답 한두 문장으로 끝내요 |
| 두 유형에 반씩 걸리는데 한쪽 유형에 억지로 맞춰요 | 블록으로 새 구조를 조립하고 형식을 먼저 보여 줘요 |
| 상한을 맞추려고 버린 대안이나 예외를 지워요 | 문서를 나눠요 |
| 담당자, 마감일, 적용 범위처럼 듣지 못한 칸을 그럴듯하게 채워요 | `<채울 값>`이나 열린 질문으로 남기고 답 끝에 알려요 |
| 하한에 맞추려고 원문에 없는 배경이나 주의 사항을 덧붙여요 | 빠진 것을 묻거나 자리만 남겨요 |
| 문서를 파일에만 쓰고 답에는 요약만 남겨요 | 저장 위치를 듣지 못했으면 전문을 답에 보여 줘요 |
| 본문 중간에 `파일:줄`을 넣어요 | 맨 아래 코드 읽기 지도에 SHA 고정으로 둬요 |

## 마지막으로 지킬 규칙

- 의도 한 줄을 밝혔나요? 표 하나로 끝나는 질문에 문서를 만들지 않았나요?
- 유형(또는 새 구조)의 블록 순서, 길이감, 자세함, 가독성 장치, 요소를 따랐나요? 새 구조면 블록 순서를 포함한 형식을 문서보다 먼저 보여 줬나요?
- 첫 화면에서 독자가 할 일(요청, 결론, 끝 기준)이 보이나요?
- 이유, 버린 대안, 예외, 미확인이 그대로 있나요? 원문에 없는 수치·단계·명령·범위·조건을 지어 넣지 않았나요? 빈 칸은 `<채울 값>`이나 열린 질문인가요?
- 초안 마커가 남지 않았고, `lint.py`와 `visual.py`가 0건인가요(L02는 확인했으면 예외)? 코드 참조는 코드 읽기 지도에만 있나요?
