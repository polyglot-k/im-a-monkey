# monkey-clear

## 먼저 지킬 규칙

1. 쉽게 쓰라는 말은 짧게 쓰라는 말이 아니에요. 이유, 전제, 예외, 아직 모르는 것은 남기고, 읽는 순서와 문장으로 쉽게 만들어요.
2. 한 문장에는 한 사실만 담아요. "A라서 B가 되고 C 때문에 D"처럼 인과 여러 단계를 한 문장에 접지 않아요.
3. 시스템 식별자·설정 이름·약어(`minReplicas`, TTL 같은 것)는 사람 말 설명을 먼저 쓰고 뒤에 괄호나 코드 표기로 붙여요.
4. 팀이나 사용자가 쓰는 용어("정산 대기 건" 같은 말)는 그대로 써요. 번역하거나 새 이름을 짓지 않고, 처음 나올 때 한 번만 풀어요.
5. 용어 목록을 결론이나 단계 앞에 따로 세우지 않아요. 용어는 그 단계 문장 안에서 처음 나올 때 풀어요.

## 설명하기 전에 속으로 정할 것

묻지 않고 세 가지만 정해요. 셋 다 요청과 맥락에서 읽어요.

- **행동**: 이 사람은 읽고 나서 무엇을 하나요? 이해만 하나요, 결정하나요, 따라 하나요? 행동에 쓰이지 않는 구현 세부는 빼요. 행동에 필요한 맥락(언제 문제가 되는지, 누구에게 무엇을 부탁하면 되는지)은 넣어요.
- **시간**: 얼마나 들여 읽나요? 30초 훑기면 결론과 할 일만 앞에 두고 나머지는 뒤로 미뤄요. 정독이면 단계를 모두 펼쳐요. 어느 쪽이든 이유, 전제, 예외는 빼지 않아요.
- **아는 정도**: 이 주제를 처음 보나요, 아는데 이 경우만 모르나요? 처음 보는 사람에게는 결론 바로 다음에 예시를 두고 정의는 그 뒤에 줘요. 아는 사람에게는 결론과 차이점을 먼저 줘요.

## 쓰는 순서

1. **결론 한두 문장.** 질문에 대한 답을 맨 앞에 둬요. 배경부터 쌓아 올리지 않아요.
2. **예시 (처음 접하는 독자면).** 결론 바로 다음, 정의보다 먼저 예시를 둬요. 이미 아는 독자에게는 예시를 빼거나 펼치기 뒤에 확인용으로 둬요.
3. **펼치기.** 결론이 왜 그런지 단계로 풀어요. 아래 "압축 풀기"를 따라요.
4. **남은 맥락.** 예외, 아직 확인하지 않은 것, 독자가 할 일을 짧게 붙여요.

채팅에서는 제목을 달지 않고 문단으로 답해요. 순서가 있는 단계만 번호 목록으로 써요. 볼드와 불릿을 장식으로 쓰지 않아요.

## 압축 풀기 (W01)

식별자와 약어와 인과가 한 문장에 몰린 설명을 받으면, 또는 내가 그렇게 쓰려 하면 이렇게 풀어요.

1. 문장 속 인과를 "무엇이 → 무엇을 일으켰다" 단계로 나눠 속으로 목록을 만들어요. 화살표(→) 하나가 한 단계예요.
2. 단계마다 한 문장을 써요. 각 문장에는 주어(누가, 무엇이)를 밝혀요(W06).
3. 식별자는 그 단계를 사람 말로 쓴 뒤에 붙여요. 처음 나오는 약어는 그 단계 문장 안에서 한 번 풀어요(T02). 용어 풀이를 단계 앞에 따로 모으지 않아요.
4. 원문에 있던 대응, 수치, "아직 모름"은 하나도 빼지 않아요. 원문에 없는 원인은 단정해서 붙이지 않아요. 추측이 필요하면 "추정"이라고 밝혀요.

## 문장 규칙

| 규칙 | 나쁜 예 → 좋은 예 |
|---|---|
| 사람 말 먼저, 식별자 뒤 | "`retry_after`가 30이라 그래요" → "30초 뒤에 다시 시도하라는 응답(`retry_after: 30`)을 받아서 그래요" |
| 주체를 밝혀요 (W06) | "배포 전에 확인돼야 해요" → "배포하는 사람이 배포 전에 확인해요" |
| 조건을 지시 앞에 (W07) | "캐시를 비우세요. 단 점심시간엔 안 돼요" → "점심시간이 아니면 캐시를 비우세요" |
| 출발과 도착을 드러내요 (W08) | "위 브랜치로 합치세요" → "`fix/login`을 `main`으로 합치세요 (`fix/login → main`)" |
| 원문에 값이 있으면 흐린 말 대신 값 | "꽤 오래 걸려요(로그상 보통 2~3분)" → "보통 2~3분 걸려요". 원문에 값이 없으면 지어내지 말고 "확인하지 못했어요"로 밝혀요 |

## 용어 (T01·T02)

용어는 두 종류로 나눠 다뤄요.

- **팀·사용자 용어**(사람이 부르는 이름): 그대로 쓰고 처음 나올 때 한 번 풀어요. 예: "정산 대기 건(결제는 됐지만 판매자에게 아직 돈을 보내지 않은 주문)이 쌓였어요." 두 번째부터는 그냥 "정산 대기 건"이에요. 설명하다 내가 붙인 임시 이름("이중 대기 구조")을 팀 용어처럼 쓰지 않아요.
- **시스템 식별자**(설정 이름, 변수, 약어): 사람 말 설명이 먼저, 식별자는 뒤예요. 예: "한 번에 가져오는 개수의 상한(`batch_size`)을 100으로 줄였어요."
- 두 종류 모두 풀이는 그 말이 처음 나오는 문장 안에서 해요. 답 앞머리에 용어집을 세우지 않아요.
- 사용자가 정의해 준 용어는 그 정의 그대로 풀어요. 내 말로 바꾼 정의를 새로 만들지 않아요.

## 숫자와 확신

- 숫자가 세 개 이상이거나 전후·항목 비교일 때는 문장 대신 표로 보여줘요. 표 앞에는 무엇을 보여 주는 표인지 한 문장을 둬요.
- 채팅에서 값 몇 개를 비교·요약해 달라는 요청에는 표를 하나만 쓰고 사용자가 준 값만 넣어요. 빠진 조건(기간, 기준, 단위)은 가정해서 채우지 말고 질문 하나로 물어요.
- 측정한 값, 추정한 값, 확인하지 못한 것을 구분해요. 예: "어제 로그로 잰 값은 4초예요. 오늘도 비슷할 거라고 추정해요. 모바일에서는 아직 확인하지 못했어요."
- 원문이나 사용자가 "확인 예정"이라고 한 것을 "해결됐다"로 바꾸지 않아요.

## 그림이 필요할 때

여러 구성 요소가 오가는 흐름, 시간 순서, 상태 변화처럼 문장으로 따라가기 어려우면 `monkey-visual`로 넘겨요. 그림이 답할 질문 하나를 함께 넘겨요. 채팅에서 간단한 흐름은 번호 목록으로 충분해요.

## 다른 스킬과 나누는 일

- 문서 한 편(스펙, ADR, 보고서)의 구조를 정하는 일은 `monkey-doc`이에요. 이 스킬은 문단과 문장 단위로 쉽게 만드는 일이에요.
- 이미 쓴 글의 AI 티·번역투를 고치는 일은 `monkey-human`이에요.

## 자주 하는 실수

| 실수 | 대신 |
|---|---|
| "쉽게"를 "짧게"로 읽고 예외와 미확인을 버려요 | 문장을 쉽게 하고 맥락은 남겨요 (S09) |
| 화살표 사슬(A → B → C)을 그대로 옮겨요 | 화살표 하나를 한 문장으로 풀어요 |
| 약어를 풀지 않고 "이건 아시겠지만"으로 넘어가요 | 처음 한 번 풀어요 |
| 쉬운 말로 바꾼다며 팀 용어를 번역해요 | 원어 그대로 쓰고 풀이를 붙여요 |
| 처음 보는 사람에게 정의부터 늘어놓아요 | 결론 다음에 예시를 두고 정의는 뒤에 둬요 |
| 용어 목록을 결론이나 단계 앞에 따로 세워요 (독자가 누구든) | 용어는 그 단계 문장 안에서 처음 나올 때 풀어요 |
| 값 비교를 받고 없는 조건을 가정해 칸을 채워요 (서버 두 대 응답 시간인데 "지난 한 달 평균"으로 적어요) | 받은 값만 표에 넣고 "어느 기간 기준인가요?"를 한 번 물어요 |
| 독자가 쓰지 않을 구현 세부를 덧붙여요 | 읽고 나서 할 행동에 필요한 것만 남겨요 |

## 마지막으로 지킬 규칙

- 보내기 전에 문장마다 물어요. 이 문장에 사실이 둘 이상 있나요? 있으면 나눠요.
- 식별자가 사람 말 설명보다 먼저 나온 문장이 있으면 순서를 바꿔요.
- 용어집으로 시작했으면 풀이를 각 단계 문장 안으로 옮겨요.
- 쉽게 만들면서 이유, 전제, 예외, 미확인이 빠지지 않았는지 원래 내용과 맞춰 봐요. 팀 용어는 그대로예요.
