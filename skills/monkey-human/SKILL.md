# monkey-human

## 먼저 지킬 규칙

1. 사실, 주장, 수치, 고유명사, 날짜, 부정, 인용, 링크는 바꾸지 않아요. 확신의 정도도 주장이에요. "~로 보입니다"를 단정으로 바꾸지 않아요.
   - 근거 없이 붙은 의의·효과 꼬리(A05, A06, A11)와 흐린 강조어(W04)는 주장이 아니라 수사예요. 지우고 지운 자리를 다른 말로 채우지 않아요.
2. 진단에 걸리지 않은 문장은 손대지 않아요. 취향 차이는 진단이 아니에요.
3. 원문에 없는 문장, 설명, 예시, 효과를 넣지 않아요. 독자에게 친절해 보여도 지어낸 내용이에요.
4. 형식과 순서는 그대로 둬요. 문단을 목록·표·제목으로 바꾸거나, 문장과 문단의 순서를 옮기거나, 볼드를 새로 붙이지 않아요. 글쓴이가 고른 말투(합니다체·해요체·~다)도 유지해요.

## 모드

- `fix`(기본): 진단된 문장만 고친 글을 돌려줘요.
- `scan`: 글은 그대로 두고 수치와 고칠 곳 표본 3곳만 보여줘요. "AI 같아?", "점수"처럼 고치라는 말이 없으면 `scan`이에요.

문장·말투·표현만 다듬어요. 문서 구조를 다시 잡거나 새로 짜 달라는 요청이면 `monkey-doc`으로 넘겨요.

다른 스킬이 부를 때는 "`monkey-human`을 `fix` 모드로, 대상 파일 경로와 함께"라는 형태로 불러요. 이때는 그 파일을 직접 고치고 보고만 대화에 남겨요.

## 도구

이 스킬이 로드될 때 보이는 base directory를 `<base>`라고 할게요. 스크립트는 저장소 루트의 `scripts/`에 있어요.

```
python3 <base>/../../scripts/lint.py FILE --json       # 번역투·AI 상투어 위치와 ID
python3 <base>/../../scripts/rhythm.py FILE --json     # 문장 길이·어미 반복·불릿·볼드
python3 <base>/../../scripts/preserve.py ORIG REV --json  # 숫자·토큰·부정·링크 보존, edit_rate
```

- 진단 기준과 고친 예는 `<base>/diagnose.md`에 있어요. 진단 전에 읽어요.
- 사용자가 배운 패턴이 `$XDG_CONFIG_HOME/im-a-monkey/overlay/antipatterns.md`(없으면 `~/.config/im-a-monkey/overlay/antipatterns.md`)에 있을 수 있어요. 파일이 있으면 함께 읽어요.
- Python이 없거나 스크립트·파일 쓰기가 실패하면 멈추지 말고 `diagnose.md`의 "스크립트 없이 진행할 때의 체크리스트"를 손으로 따라가요. `diagnose.md`도 못 읽으면 아래 "고치는 법 요약"으로 진단해요. 어느 쪽이든 보고에 한 줄 적어요.

## 절차

1. **원문 저장.** 원문을 시스템 임시 폴더의 파일에 그대로 저장해요. 파일 경로로 받았으면 그 파일을 임시 폴더로 복사해요. 사용자의 작업 폴더에는 임시 파일을 만들지 않아요.
2. **수치 확보.** 원문에 `lint.py --json`과 `rhythm.py --json`을 돌려요. 못 돌리면 같은 끝맺음이 몇 번 이어지는지 직접 세요.
3. **진단.** `diagnose.md`를 읽고 이 글을 지배하는 패턴 3~6개를 ID로 골라요(예: A01, A02, A14, W03). 스크립트 결과에 판단 패턴(A10~A14, W01, W06, W07)을 더해요. 걸린 문장 목록도 함께 만들어요.
   - 고를 패턴이 없으면 진단은 "고칠 곳 없음"이에요. 원문을 그대로 돌려주고 왜 그렇게 봤는지 한두 줄로 말해요. 억지로 하나라도 고치지 않아요.
4. **겨냥 윤문.** 3에서 목록에 오른 문장만 고쳐요. 걸린 문장은 그 안에서 자연스러운 한국어가 될 때까지 고쳐요. 패턴 단어 하나만 바꾸고 딱딱한 문장을 남기면 덜 고친 거예요. 걸리지 않은 문장은 한 글자도 바꾸지 않아요. 긴 글(대략 1,500자 이상)은 문단 단위로 나눠 고쳐요.
5. **보존 대조.** 결과를 같은 임시 폴더의 파일에 저장하고 `preserve.py 원문 결과 --json`을 돌려요. 대조가 끝나면 임시 파일을 지워요.
   - `ok`가 false면 어긋난 문단을 찾아 원문으로 되돌리고 무엇이 걸렸는지(빠진 숫자, 부정어 증감 등) 보고해요. 되돌린 뒤 다시 대조해요.
   - 예외는 하나예요. A07(`단순히 X가 아니라 Y`)을 Y만 남기도록 고쳐서 수사로 쓴 "아니라"가 빠진 경우예요. `negation_delta`가 그 개수만큼만 줄었다면 되돌리지 않고 "설명된 예외"로 보고해요. 다른 부정어가 바뀌었다면 되돌려요.
6. **보고.** 아래 출력 형식대로 써요.

## 출력 형식

`fix`일 때는 고친 글을 먼저 원문과 같은 형식으로 보여줘요. 원문이 평문 문단이면 평문 문단으로 줘요. 코드 블록이나 인용 블록으로 감싸지 않아요. 그 아래에 보고를 짧게 붙여요.

```
고친 패턴: A01 3건, A02 2건, A14 4건, W03 1건
린트: 9건 → 0건 · 리듬 경고: A15 같은 어미 연속 7회 → 3회
의미 보존: 통과 (edit_rate 0.31)
되돌린 문단: 없음
손대지 않은 것: "~로 보인다"의 추정은 그대로 살렸어요.
```

- 패턴 ID마다 고친 예를 하나씩 들 필요는 없어요. 독자가 의아해할 만한 변경만 한 줄로 설명해요.
- 원문에 있던 애매한 점(주체 불명, 근거 없는 효과 주장)은 고치지 말고 "확인할 것"으로 따로 적어요.
- 스크립트를 못 돌렸으면 `edit_rate` 대신 "바꾼 문장 수 / 전체 문장 수"를 쓰고 보존 대조는 손으로 맞춘 목록(숫자·부정어·링크)을 한 줄로 적어요.

`scan`일 때는 글을 고치지 않고 이렇게만 보여줘요.

```
린트 9건 (A01 3, A02 2, W03 1, ...) · 리듬 경고 1건
지배 패턴: A01, A02, A14
표본 3곳: 원문 문장 → 고친다면 이렇게
```

## 자주 하는 실수

| 실수 | 대신 |
|---|---|
| 잘 쓴 문장도 "더 매끄럽게" 다시 써요 | 진단 목록에 없으면 그대로 둬요 |
| 문단을 불릿 목록과 소제목으로 재구성해요 | 형식은 원문 그대로. 구조 개편은 이 스킬의 일이 아니에요 |
| 이해를 돕는 설명이나 행동 안내를 덧붙여요 | 원문에 없는 문장은 넣지 않아요. 필요해 보이면 "확인할 것"에 적어요 |
| "주 2회까지만 무료"를 "무료가 보장되지 않음"으로 바꿔요 | 제약의 범위와 방향을 원문 말 그대로 지켜요 |
| 빈 수식어를 지운 자리에 새 수치나 효과를 채워요 | 지우기만 해요. 원문에 있는 수치만 써요 |
| 의미 보존을 "정보는 그대로예요"라고 말로만 주장해요 | `preserve.py` 결과나 손으로 맞춘 목록을 보여줘요 |

## 마지막으로 지킬 규칙

- 과윤문도 실패예요. `edit_rate`가 0.4를 넘으면 왜 그만큼 바꿨는지 보고에 한 줄로 밝혀요. 리듬(A15)과 쉼표(W09)만 고칠 때는 0.3 안쪽에서 끝내요.
- 진단에 걸리지 않은 문장은 그대로, 사실·수치·부정·인용·링크도 그대로예요. 하나라도 어긋난 문단은 원문으로 되돌려요.
